# Обрій — погода в містах світу

Багатосторінковий застосунок на React: пошук міст, каталог із фільтрами й пагінацією, сторінка міста з прогнозом на 7 днів і погодинним прогнозом на сьогодні, «Обране», яке переживає перезавантаження.

- **Опублікований застосунок:** `https://ВСТАВТЕ-АДРЕСУ`
- **Репозиторій:** `https://github.com/ВСТАВТЕ-ЛОГІН/ВСТАВТЕ-НАЗВУ`

## Запуск

```bash
npm install
npm run dev         # розробка, http://localhost:5173
npm run build       # збірка в папку dist
npm run preview     # локальна перевірка збірки
```

Змінні (необов'язково, див. `.env.example`): `VITE_GEOCODING_URL`, `VITE_FORECAST_URL` — інші адреси API, `VITE_BASE` — підкаталог, якщо сайт не в корені.

## API

Open-Meteo, ключ не потрібен. Адреси задані в одному місці — `src/api/config.js`, усі запити — лише в `src/api/weather.js`.

| Що | Ендпоінт | Параметри |
|---|---|---|
| Пошук міст | `GET geocoding-api.open-meteo.com/v1/search` | `name`, `count=100`, `language=uk`, `format=json` |
| Одне місто за id | `GET geocoding-api.open-meteo.com/v1/get` | `id` |
| Температура для списку міст | `GET api.open-meteo.com/v1/forecast` | `latitude`, `longitude` (кілька через кому), `current`, `temperature_unit`, `timezone=auto` |
| Прогноз на 7 днів | `GET api.open-meteo.com/v1/forecast` | `current`, `daily` (8 величин), `forecast_days=7`, `temperature_unit`, `timezone=auto` |
| Погодинний прогноз на сьогодні | `GET api.open-meteo.com/v1/forecast` | `hourly` (4 величини), `forecast_days=1`, `temperature_unit`, `timezone=auto` |

Поведінка, яку враховує застосунок:

- Порожній результат пошуку — це **HTTP 200 без поля `results`**, а не помилка. Каталог показує порожній стан.
- Для кількох координат прогноз приходить **масивом** (в тому ж порядку), для однієї — об'єктом. Адаптер приводить обидва випадки до одного вигляду.
- Невідомий `id` у `/get` → «місто не знайдено» (404 або 400 з `error: true`). Нечисловий `id` у адресі застосунок відсіює без запиту.
- Мережева помилка, 429, 5xx і зламана відповідь мають окремі повідомлення.
- Дати й години приходять за місцевим часом міста (`timezone=auto`), тому «Зараз» у погодинному прогнозі рахується за зсувом поясу з відповіді.

### Де виконується кожен фільтр

| Фільтр | Де | Чому |
|---|---|---|
| Одиниці температури | **сервер**, параметр `temperature_unit` | API сам повертає значення в потрібних одиницях; зміна одиниць перезавантажує погоду |
| Країна | **клієнт** | геокодер не вміє фільтрувати за країною разом з назвою. Фільтр діє на ті (до 100) міста, що вже знайдені за назвою, і в інтерфейсі це сказано |
| Сортування (збіг / назва / населення) | клієнт | працює над тими самими знайденими містами |
| Сторінки (12 міст) | клієнт | усі знайдені міста вже завантажені; температура запитується лише для міст поточної сторінки |

## Сторінки

| Маршрут | Вміст |
|---|---|
| `/` | головна: пошук, швидкі добірки з готовими фільтрами, шість великих міст із температурою |
| `/catalog` | стан очікування до пошуку, потім міста; увесь стан — в адресі (`?q=&country=&unit=&sort=&page=`) |
| `/city/:id` | місто, поточна погода, прогноз на 7 днів, окремий блок «Сьогодні по годинах» |
| `/favorites` | обрані міста з актуальною температурою |
| `/about` | про застосунок, джерела даних, технології |
| `*` | сторінка 404 |

## Архітектура

```
src/
  api/         fetch, помилки, кеш, адаптери, коди погоди, функції weather.js
  context/     FavoritesContext, ThemeContext
  hooks/       useResource, useWeatherData, useFavorites, useTheme, useDebouncedValue, useDocumentTitle
  components/  Layout, CityCard, FilterPanel, Pagination, StateViews, DailyForecast, HourlyChart, WeatherIcon…
  pages/       Home, Catalog, Details, Favorites, About, NotFound
  utils/       форматування, шкала кольорів температури, параметри каталогу
  styles/      токени та SCSS
```

Де що живе:

- **URL** — запит, країна, одиниці, сортування, сторінка, `id` міста.
- **Context** — «Обране» і тема.
- **Локальний стан** — відкрита панель фільтрів, текст у полі до паузи.
- **Кеш** — відповіді API, поза React (`src/api/cache.js`).

### Залежні запити на сторінці міста

1. `useCity(id)` — місто. Якщо його вже бачили (каталог, добірка), береться з довідника без запиту.
2. `useForecast(city, unit)` — основний вміст (поточна погода й 7 днів). Стартує, коли відомі координати.
3. `useHourly(city, unit)` — пов'язані дані. Теж стартує, коли відомі координати, **не чекає** на пункт 2 і має свої скелетон, помилку й порожній стан.

## Кеш

Два `Map` у пам'яті, ключ — повна адреса запиту, разом зі значенням зберігається час запису:

- міста (геокодер) — застарівають через **1 годину**;
- погода — через **10 хвилин** (Open-Meteo оновлює поточні дані приблизно раз на 15 хвилин).

Застарілий запис видаляється при читанні, максимум 100–150 записів, найстаріші витісняються. Помилки в кеш не потрапляють. Хук `useResource` спочатку питає кеш: свіжа відповідь показується одразу, без скелетона й запиту — тому «Назад» з міста до каталогу миттєвий. Окремо працює довідник міст (`cityIndex`): сторінка міста не питає `/get`, якщо місто вже було в результатах пошуку.

## Хостинг і маршрути SPA

Застосунок — один `index.html`; маршрути `/city/123` існують лише в JavaScript. Без налаштування хостинг шукає файл `city/123`, не знаходить і віддає 404. Рішення — переписування будь-якого шляху на `index.html`:

- **Netlify** — `public/_redirects` (`/*  /index.html  200`) потрапляє в `dist`. Build command: `npm run build`, publish directory: `dist`.
- **Vercel** — `vercel.json` з rewrite на `/index.html`. Framework: Vite.
- **GitHub Pages** — `.github/workflows/deploy.yml` збирає командою `npm run build:pages`, яка копіює `index.html` у `404.html` (Pages віддає її для невідомих шляхів). `VITE_BASE=/<назва-репозиторію>/` виставляється в workflow; у Settings → Pages оберіть Source: GitHub Actions.

## Завдання підвищеної складності

1. **Ліниве завантаження сторінок** — `React.lazy` + `Suspense` у `src/router.jsx`; кожна сторінка збирається в окремий файл. Вхідний бандл ≈ 307 kB (98 kB gzip) без сторінок.
2. **Кеш зі строком придатності** — див. розділ «Кеш».
